   # Total: O(N + R) - LINEAR!

ISSUE 1: Geographic CRS Area Calculation
-----------------------------------------
Problem:
- Raster in EPSG:4326 (degrees), not meters
- Pixel area calculated as ~8e-09 (square degrees)
- Result: min_pixels = 123 billion (impossibly large)

Fix:
- Detect geographic CRS with crs.is_geographic
- Convert degrees to meters at center latitude
- Store bounds in __init__ for repeated access

Code:
```python
if self.crs.is_geographic:
    center_lat = (self.bounds.top + self.bounds.bottom) / 2
    meters_per_degree_lat = 111320
    meters_per_degree_lon = 111320 * math.cos(math.radians(center_lat))
    pixel_width_m = abs(self.transform[0]) * meters_per_degree_lon
    pixel_height_m = abs(self.transform[4]) * meters_per_degree_lat
    pixel_area = pixel_width_m * pixel_height_m
else:
    pixel_area = abs(self.transform[0] * self.transform[4])
```

ISSUE 2: Slow Statistics Calculation
-------------------------------------
Problem:
- Original loop: O(R × N) complexity
- np.where() scanned 290M pixels for EACH region
- With 27,618 regions: 7.5 trillion pixel comparisons
- Estimated time: 24+ minutes

Fix:
- Use np.bincount() for pixel counts: O(N)
- Use scipy.ndimage.find_objects() for bboxes: O(N)
- Reduced to O(N + R) complexity
- Result: <1 second

ISSUE 3: Empty DataFrame Sorting
---------------------------------
Problem:
- df.sort_values() failed when no regions found
- KeyError: 'area_m2'

Fix:
```python
if len(self.region_stats) > 0:
    self.region_stats = self.region_stats.sort_values('area_m2', ...)
```

ISSUE 4: Polygon Area Calculation Warning
------------------------------------------
Problem:
- GeoPandas geometry.area returns square degrees for EPSG:4326
- Warning: "Geometry is in a geographic CRS. Results likely incorrect"

Fix:
- Reproject to appropriate UTM zone before area calculation
- Auto-detect UTM zone from center longitude
- For Alaska ~160°W, 60°N: UTM Zone 3N (EPSG:32603)

Code:
```python
if self.crs.is_geographic:
    center_lon = (self.bounds.left + self.bounds.right) / 2
    utm_zone = int((center_lon + 180) / 6) + 1
    utm_epsg = 32600 + utm_zone if bounds.bottom >= 0 else 32700 + utm_zone
    gdf['area_m2'] = gdf.to_crs(epsg=utm_epsg).geometry.area
```

TROUBLESHOOTING
================================================================================

ISSUE: "ImportError: No module named 'cupy'"
SOLUTION: pip install cupy-cuda12x (or cupy-cuda11x for CUDA 11)

ISSUE: "CUDA out of memory"
SOLUTION:
- Raster too large for GPU memory
- Reduce raster size or use CPU fallback (use_gpu=False)
- Or implement Dask chunking for very large rasters

ISSUE: "Too many regions identified"
SOLUTION:
- Increase min_area_m2 threshold
- Add morphology_cleanup to connect fragmented pixels
- Filter results by size after processing

ISSUE: "Areas in statistics don't match QGIS"
SOLUTION:
- Check CRS - script handles EPSG:4326 correctly
- For other CRS, reproject to UTM before processing
- Verify pixel size in transform matrix

ISSUE: "Processing still slow"
SOLUTION:
- Ensure GPU is being used (check "Mode: GPU (CuPy)" in output)
- Check GPU utilization with nvidia-smi
- Verify CUDA installation: python3 -c "import cupy; print(cupy.cuda.runtime.getDeviceCount())"
